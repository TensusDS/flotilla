## Findings

W1. **friction - `/flotilla:spawn` does not offer "this session leads".** In an already onboarded project the person
opened a fresh session, ran `flotilla doctor` (all ok) and the session noted it holds no post. The recommended way
to lead a fleet - `flotilla spawn --lead`, then `--fill` on the next message - is offered only by onboarding's last
step. `/flotilla:spawn` with no arguments raises the default composition with a background orchestrator, and
nothing mentions `--lead`; a person who onboarded yesterday cannot find the recommended path today. Fix direction:
`/flotilla:spawn` with no arguments asks the same question onboarding asks - this session leads (recommended), a
background orchestrator, or a named composition - and walks the lead path the onboarding skill describes.
