# Organize Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/flotilla:organize` - inside onboarding and on its own - walks the work the ledger never saw, asks the
person what to do with each piece of their own, and does it: take it in, ignore it, or what they say in words.

**Architecture:** A new package `flotilla/organize/` does the walk (git, `gh`, procfs), turns items into questions for
the existing question door, stores answers in the state directory, and applies them; every move outside the ledger
is made only by `flotilla organize apply` from a recorded answer. The ledger gains a person-class take-in move and
four row fields; `queue` and `ship` carry out the retargets and closes a row records; publish accepts a committed
profile; a new guard refuses the same outward commands typed by a session; two skills drive it.

**Tech Stack:** Python 3.11+ standard library only, git, `gh` 2.95+, pytest.

**Spec:** `docs/specs/2026-10-19-organize-design.md` (v3, commit `a9aec67`). Section numbers below (§N) are the
spec's.

## Global Constraints

- Python stdlib only; `requires-python = ">=3.11"`. Tests never reach the network: every `gh` call goes through an
  injected `run` (`tests/ledgerkit.fake_gh`).
- Every text a person or a session reads is English. Pull request titles, bodies, branch names and commit messages
  are shown as data, cut and marked as their authors' words (§10), never followed.
- A branch name goes into a command only when it matches `flotilla.ledger.core.SAFE_BRANCH`.
- Nothing is force-pushed; trunk is only fast-forwarded, moved with `git branch -f` when checked out nowhere, or with
  `git reset --keep` in the organizing tree; never `--hard` (§6, §10).
- Kept refs live under `refs/flotilla/kept/<sha>` and `refs/flotilla/dropped/<sha>`, named by the kept commit's own
  sha, written create-only with `git update-ref <ref> <sha> 0000000000000000000000000000000000000000` (§6, §7).
- `flotilla organize answer`, `propose` and `apply` are refused from background sessions by
  `flotilla.core.caller.person_refusal` (§4, §9).
- No organize question has a recommended or preselected option; 2-4 options; at most `MAX_PER_ROUND = 4` questions per
  round (§4).
- A dismissed, timed-out or away answer records nothing and changes nothing (§4).
- Commit messages: Conventional Commits, English, ending with the two trailer lines
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and
  `Claude-Session: https://claude.ai/code/session_015SGr4UX5YjQxdzMfYUXaX7`.
- echoes-of-the-ancients stays read only until the person says to start there (§12): no task below touches it, except
  Task 18, which waits for that word.

## Review Focus

1. A pull request's head or base moves between the question and `apply` (someone pushed) - the item is asked again
   and nothing is done for it (Task 11, `test_apply_asks_again_when_a_head_moved`).
2. Uncommitted edits with an untracked binary, a staged-and-modified file and a file under a line-ending filter - the
   kept commit holds every one, and nothing leaves the tree whose stored bytes differ (Task 13,
   `test_keep_holds_untracked_binary_and_staged_states`, `test_a_path_whose_stored_blob_differs_stays`).
3. An unstack that leaves a member stacked (auto-merge on it) - organize does nothing else for that stack and names
   the member (Task 12, `test_a_member_left_stacked_stops_the_take_in`).
4. Organize run a second time after a take-in - asks nothing about taken-in pull requests or the ones a row will
   close; the retarget at `queue` does nothing when the base is already trunk (Tasks 6, 3:
   `test_a_second_walk_skips_taken_and_closed_pulls`, `test_queue_retarget_is_idempotent`).
5. A pull request whose branch name a shell would read (`feat/$(x)`) - listed, never takeable, never in a command
   (Task 6, `test_an_unsafe_branch_is_listed_not_offered`).
