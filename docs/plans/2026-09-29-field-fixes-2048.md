# Field Fixes, Part 5: What the 2048 Fleet Found — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the defects the second field test found: a judge's fix row that `tree switch` cannot take, a fix
settled by another row that leaves the broken row unwalkable for ever, `fleet down` leaving live sessions running,
and four gaps in what the posts say.

**Architecture:** Three code fixes and one text pass. `tree.switch` creates the branch from trunk for an open row of
yours that has none (a fix row `broke` filed). A fix row released `--settled-by` a delivered row counts as that
row's delivery wherever a broken row asks whether it is fixed — the judge's `walked` and the `broken_unfixed`
deviation — through one helper in `views`. `retire` counts any session the census lists as running. The
arrangement skill and the orchestrator, producer and sender posts say: announce to the fleet, declare a split's
dependency, put a change of the request to the person, name each branch's own merge.

**Tech Stack:** Python 3.11+ stdlib, git, pytest via `uv`.

**Spec:** the field test `docs/field-tests/2026-09-29-game2048-fleet.md` — findings G1, G3, G5, G6, G7, G9, G10,
G11, G12 and setup note S7; `docs/specs/2026-09-22-flotilla-design.md` sections 6.3, 7.4, 7.5.

## Decisions (the executor's, 2026-09-29; the person approved fixing the findings)

1. **`tree switch` takes an open row of yours that has no branch** (G6): it creates the branch from trunk in the
   home tree, records the base and the tree, and makes no new row.
2. **A fix settled by a delivered row is delivered** (G9, G10): a fix row `released` with evidence `settled_by`
   naming a delivered row stands, for the broken row, as that delivered row — its merge must be in the walked
   build, and `broken_unfixed` does not fire. One helper, `views.fix_delivery(rows, fix, profile) -> Row | None`.
3. **A session the census lists is running, whatever its state** (G12): a background session whose turn is done is
   still a process, and may hold a background task. `retire` stops it.
4. **The posts say four things they did not** (G1, G3, G5, G11): a session announces itself to the fleet's seats
   (`flotilla fleet`), not to every session on the machine; an orchestrator that splits a task into rows whose
   parts build on each other tells the later one to claim with `--requires <branch>`; a change to what the person
   asked (a different control, a dropped feature) is a question to the person through the orchestrator before it is
   built; the sender lands each branch at that branch's own merge commit. The README says what `--scope project`
   commits (S7).

`views.py`:

```python
def fix_delivery(rows: dict[str, Row], fix: Row, profile: dict) -> Row | None:
    """The delivered row that carries a fix: the fix row itself, or the delivered row it was settled by (G9)."""
    if delivered(fix, profile):
        return fix
    if fix.state != "released" or not fix.history:
        return None
    wanted = (fix.history[-1].get("evidence") or {}).get("settled_by") or ""
    other = rows.get(wanted)
    return other if other is not None and delivered(other, profile) else None
```
