# Garbage collection, stage 2: the archive and the person's word - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tree that stage 1 keeps only because it holds files nothing makes again stops piling up: a file with a
byte-identical twin that survives the pass goes (tier 1), unique ignored data goes to the archive (tier 2: small is
told after, large is asked before), and everything else is put to the person as one question per piece of work,
whose recorded answer only the collector carries out (tier 3).

**Architecture:** Five new modules in `flotilla/gc/`: twins by content with a hash cache (`twins.py`), the archive
with its manifest and restore (`archive.py`), the questions and their store (`questions.py`, `store.py`), and the
apply step that carries out recorded answers (`apply.py`), plus the CLI (`commands.py`). `ignored.py` grows from
rule 1 to rules 1-5 and returns a classification instead of a list; `trees.py` splits a verdict's reasons into what
breaks (`reasons`) and what only the person settles (`doubts`), and names the files bound for the archive;
`sweep.py` and `remove.py` archive small tier-2 files inside the removal lock. A new always-on guard
(`flotilla/guards/gc.py`) refuses sessions removing fleet trees, fleet branches, parked refs or the archive by
hand. A person-only skill (`skills/gc/`) asks the questions the way `skills/organize/` does.

**Tech Stack:** Python 3.11+ stdlib (`hashlib`, `mimetypes`, `shutil`), git >= 2.38 through `subprocess`, pytest
through `uv run --with pytest python -m pytest -p no:cacheprovider -q tests/`.

**Spec:** `docs/specs/2026-10-21-gc-design.md` (approved by the person 2026-10-27). Sections implemented here: 2
(the table, small or large), 3 (tiers and the four answers), 6 rules 2-5, 7 (the archive, manifest, restore; not
its lifetime), 9 (questions with ids grouped by piece of work, "accept all as proposed", answers through the
question door, the apply step, the guard, warnings). Stage 1 shipped 6 rule 1, 5.x and 9's tier-1 report in 0.22.0.
Not here: stage 3 (sections 4 e-k, 8, 7's lifetime and expiry question).

## Global Constraints

- The person's rule: nothing is deleted for good without the person's recorded word (the `junk` answer); an
  unanswered question blocks only its own item, never a pass or a session's exit.
- A session relaying "the person said yes" approves nothing: `flotilla gc answer` and `flotilla gc apply` refuse a
  background session (`caller.person_refusal`), as organize's do; the skill never pre-approves them.
- Only the collector acts on an answer, and only on the answer as recorded, bound to the fingerprint of what the
  person was shown; anything that moved since is asked again.
- Twins are byte-identical by sha256 and must survive the pass: the main checkout, a declared store (`[gc] stores`),
  the archive, a blob reachable from a ref that survives (`rev-list --objects` over the pass's holders), or a tree
  the pass does not judge. Trees the pass judges are never twins for each other (rule 3 is the archive's dedup).
- Thresholds: 100 MB per tree per pass, 500 MB per pass (`[gc] archive_tree_mb`, `[gc] archive_pass_mb`); under both,
  archive and tell after; over either, ask before. Content counted once per sha256 across the pass.
- The archive: `<main checkout's parent>/<main checkout's name>-gc-archive/`; moved by rename, across filesystems
  copied, verified by sha256, then deleted; identical content stored once; a symlink is moved as a link, never
  followed. Nothing in this stage deletes from the archive.
- `MANIFEST` lines in the person's format: `<sha256>  <path now, relative to the archive>  <-  <where it came from>`,
  control characters made visible (`core.text.visible`).
- `git worktree remove --force` only in `apply.py` and `archive`-then-remove of the pass, and only after re-checking
  under the lock that nothing but archived content and regenerable files remains.
- Parked refs never expire; junk and archive both park the tree's HEAD and reflog-only commits first.
- Public tree: no personal names, home paths or other projects in code, tests or docs. Lines at most 120 characters;
  no Cyrillic in the tree. Tests that make commits pass `*IDENTITY` from `tests/ledgerkit.py`; nothing in a test uses
  `sed -i` (BSD sed differs: `1d17817`).

## Review Focus

1. **A file the main checkout has at the same path with the same size but other bytes.** Expect: not a twin; it is
   archived (tier 2), never removed. Test in Task 1.
2. **The tree changed between the question and the answer** (a file added, HEAD moved). Expect: `apply` does
   nothing to that item, says "changed since you answered", and `next` asks again. Test in Task 7.
3. **The archive on another filesystem** (`os.rename` raises `EXDEV`). Expect: copied, verified, deleted; a hash
   mismatch leaves the original in place and the tree stays. Test in Task 4.
4. **Restore onto a path that now holds a different file.** Expect: that file is not overwritten; it is named, the
   rest are restored. Test in Task 4.
5. **A symlink among the ignored files pointing outside the tree.** Expect: its target is never hashed, moved or
   deleted; the link itself is archived as a link. Test in Task 4.

## Calls this plan makes (the design left them to the builder)

1. **Trees the pass judges are never twins for each other**; rule 3 is the archive storing identical content once.
   Cost if wrong: a file is archived that had a twin in a tree which then stayed for another reason - one extra copy
   in the archive, nothing lost.
2. **The report is the letter.** The pass runs in `fleet down`, `retire` and `fleet clean`, which the orchestrator
   runs, so what it prints already reaches the orchestrator; no new sending in this stage. Stage 3's occasions
   (passes run by other sessions) bring the letters. Cost if wrong: a pass a non-orchestrator runs by hand reports
   only to that session.
3. **`archive` is not offered for a nested repository, a populated submodule or files git is told not to look at**:
   their content is not plain files to move. The person still has keep, junk and their own words. Cost if wrong:
   the person types words where a button would do.
4. **Junk parks the commits too.** Junk is about files; a commit is never lost silently (anti-goal 1). Cost if
   wrong: a parked ref the person did not need.
5. **Restore copies back and keeps the object** (another entry may point to it), and is not person-only: it removes
   nothing. Cost if wrong: the archive does not shrink on restore - stage 3's expiry empties it.
6. **One archive entry per piece of work per day** (the person's batch rule: one entry, one line, one restore).
7. **The manifest's hash is sha256** (the design's twin hash), in the person's line shape, which used md5.
8. **A tree belongs to a piece of work** when a row's `tree`, `branch` or `tip` names it, so a reviewer's seat
   standing on the work is asked about together with the builder's tree.
9. **"Accept all as proposed" covers only tier-2 large items** - the collector proposes nothing for tier 3 (section
   3: it shows the evidence and does not answer).

### Task 1: Twins by content

**Files:**
- Create: `flotilla/gc/twins.py`
- Test: `tests/test_gc_twins.py`

**Interfaces:**
- Produces:
  - `def sha256(path: Path, cache: dict) -> str` - of the file's bytes; `cache` maps `str(path)` to
    `[size, mtime_ns, digest]` and is reused while size and mtime_ns match. Never follows a symlink (a link is
    hashed as `"link:" + os.readlink`).
  - `def load_cache(state: Path, repo_key: str) -> dict` / `def save_cache(state, repo_key, cache) -> None` - in
    `<state>/gc/hashes-<repo_key>.json`, written like `organize/store.save` (0600, temp then replace); an unreadable
    file is an empty cache.
  - `@dataclass(frozen=True) class Twin: where: str; kind: str` - `kind` in `"checkout"`, `"store"`, `"archive"`,
    `"blob"`, `"tree"`; `where` is a path, or `"<blob id> on <ref>"` style text for a blob (`"reachable blob
    b1aba0df"`).
  - `class Twins` - `Twins(ledger, *, holders: list[str], sources: list[tuple[Path, str]], cache: dict)`;
    `sources` are directories with their `kind`. `find(path: Path) -> Twin | None`. Sources are walked once,
    lazily, keeping only files whose size equals a size asked about so far (re-walk when a new size arrives is
    fine; walk without following links; skip `.git`). Blobs: the file's id from `git hash-object --no-filters
    --stdin-paths` (batched), reachable when in the set of `git rev-list --objects --no-object-names --stdin`
    over `holders` (read once per `Twins`).
  - `def sources(ledger, *, untouched: list[Path], archive_root: Path) -> list[tuple[Path, str]]` - the main checkout
    (`checkout`), each `[gc] stores` entry resolved against the main checkout's parent (`store`), the archive's
    `objects/` when it exists (`archive`), and `untouched` trees (`tree`).

### Task 4: The archive

**Files:**
- Create: `flotilla/gc/archive.py`
- Test: `tests/test_gc_archive.py`

**Interfaces:**
- Consumes: `twins.sha256` (Task 1), `park.park` (stage 1).
- Produces:
  - `def root_of(ledger) -> Path` - `ledger.root.parent / f"{ledger.root.name}-gc-archive"`.
  - Layout: `objects/<sha[:2]>/<sha>` (content, stored once; a link stored as a link), `entries/<id>/entry.json`,
    `entries/<id>/edits.patch` when edits were saved, `MANIFEST` (append-only, one line per file, the person's
    format).
  - `@dataclass class Entry: id: str; when: str; tier: str; approved_by: str; tree: str; branch: str; head: str;
    files: list[dict]; patch: str; last_copies: list[dict]` - `files` items `{"sha256", "size", "from"}` (absolute
    original path); `approved_by` is `"told after: small"` or `"answer <qid> <recorded at>"`; `last_copies` items
    `{"from", "where"}` for files removed on a store or checkout twin.
  - `def entry_id(piece: str, day: str) -> str` - `<day>-<piece made safe like park.ref_name's component>`; a second
    call for the same piece on the same day reuses it (one entry per piece of work per day: the person's batch rule).
  - `def put(ledger, *, entry: str, tree: Path, files: list[str], tier: str, approved_by: str, branch: str,
    head: str, patch: bytes = b"", last_copies=()) -> Entry` - moves each file (relative to `tree`) into
    `objects/`: `os.rename`; on `EXDEV` `shutil.copy2`, verify sha256, then unlink; an object already present is
    verified and the original unlinked. Raises `ArchiveFailed` on a mismatch before touching the original, and on any
    error leaves every file not yet moved in place. Appends to `entry.json` and `MANIFEST`.
  - `def entries(ledger) -> list[Entry]`.
  - `def restore(ledger, key: str) -> list[str]` - `key` is an entry id or a tree name (its newest entry). Each file
    is copied back to `from` (the object stays: another entry may point to it); a `from` that exists with other
    bytes is not overwritten and is named; when the tree directory is gone, `git worktree add --detach <tree>
    <head>` first, then the files and `git apply` of `edits.patch`. Returns one line per thing done or refused.
  - `class ArchiveFailed(RuntimeError)`.

**Interfaces:**

  - `store.load(state, repo_key) -> dict` / `store.save(state, repo_key, data)` - `<state>/gc/<repo_key>.json`,
