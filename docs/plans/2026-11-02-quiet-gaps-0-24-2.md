# 0.24.2: the lane journal's cost, a tier only the branch adds, guards a broken profile turned off - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A waiting lane run stops burning CPU on reading the journal; a receipt runs every tier the branch's own
profile adds; a tree profile that does not parse no longer switches the guards off.

**Architecture:** No new module. `core/text.visible` returns printable ASCII as it is. `core/storage` gains a read of
the committed lines after a byte offset; `lane/book.Book` keeps the folded bookings per process and folds only the
lines appended since. `ledger/receipts` takes the tiers a revision's own profile adds beside trunk's, in the run and
in every check. `guards/rules.rules_for` and `ledger/commands.trunk_rules` name trunk without parsing the tree's
profile when it does not parse.

**Tech Stack:** Python 3.11+ stdlib, git >= 2.38 through `subprocess`, pytest through
`uv run --with pytest python -m pytest -p no:cacheprovider -q tests/`.

**Spec:** `TODO.md` at 56eb4af: "A waiting run burns a fifth of a core while it polls" (twosuns item 14, measured
2026-11-02), and under "Receipts, guards and the profile" the first two items (void-lanes-online). Out of scope: the
journal's compaction and a blocking wait (left in TODO), `onboard check` and `[rig]`, `inbatch` in direct mode.

## Global Constraints

- The journal stays append-only and its format unchanged: a seat on 0.21.0 reads what 0.24.2 writes, and the reverse.
- What a reader is shown is unchanged: `visible` of any string returns exactly what it returns today.
- A fold from the cache equals a fold of the whole file, booking for booking, field for field.
- A receipt never runs fewer tiers than trunk's profile names, and a tier trunk names keeps trunk's command.
- Public tree: no personal names, home paths or other projects. Lines at most 120 characters; no Cyrillic.

## Review Focus

1. **The journal replaced or shortened under a cached reader** (a hand-edited file, a restore from a backup, a
   future compaction by rename): expect a full re-read, never bookings folded on a stale prefix. Test in Task 2.
2. **A torn last line while a reader caches** (a writer died mid-line, then the next append set it aside): expect
   the fragment never folded and the next committed line read once. Test in Task 2.
3. **A booking handed out, then the cache advances**: expect the caller's earlier `Booking` unchanged. Test in Task 2.
4. **A branch profile that does not parse at the revision a receipt is checked over**: expect the receipt not green,
   naming the file, never trunk's tiers alone passed as complete. Test in Task 3.
5. **A tree profile broken and origin with no default-branch ref** (a clone without `origin/HEAD`): expect trunk
   `main` assumed, said in the note, and the guards still on when that ref carries a profile. Test in Task 4.

---

## Calls this plan makes

1. **The cache is per process and keyed by the file's identity** (device, inode) and the committed byte offset, with
   the last committed byte re-checked as `\n`; anything else re-reads the whole file. A waiter is one process polling
   for minutes, so its cache pays from the second poll.
2. **Cached bookings are never mutated after they are handed out**: folding a new event copies the booking first.
3. **Branch tiers are a union by name**: trunk's tiers as trunk names them, then each tier of the revision's own
   profile whose name trunk lacks. A tier with trunk's name but another command runs trunk's, and the receipt says so.
4. **A broken tree profile makes the guards follow trunk's rules** with a note, rather than refusing every command: the
   session must still be able to run git and fix the file.
