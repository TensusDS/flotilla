# 0.25.0: projects sharing one machine - a fair lane and a shared rig session - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On a machine two projects share, a freed lane slot goes to the project served least recently when the
person turns `fair` on, and a rig session serves only the projects the person shared it with, showing each one's
spend.

**Architecture:** The lane keeps its journal and its count of slots. `Book.grant` gains a `share` mode and picks the
fair choice from the bookings it already folds under the lock; bookings are written under rule 2 and a `held` event
records the path it took. The commands read `machine.toml` `lane_share` on each poll, as they read the capacity.
The rig journal's session gains a `projects` list, written by `rig open` and by new person-only `rig share` and `rig
unshare`; `rig run`, `rig up` and `rig down` refuse a project not on it; `rig status` splits each machine's minutes
among the runs on it.

**Tech Stack:** Python 3.11+ stdlib, pytest through `uv run --with pytest python -m pytest -p no:cacheprovider -q
tests/`.

**Spec:** `docs/specs/2026-11-02-project-share-design.md` (approved by the person 2026-11-02).

## Global Constraints

- `lane_share` unset or `"fifo"`: every admission exactly as 0.24.2, path recorded `fifo`.
- The count of slots is unchanged in every mode: live holders plus computing foreign runs against `lane_capacity`,
  decided under the journal's lock.
- A waiter under rule 2 never yields to a waiter under an older rule (spec section 3, the stall).
- A session's `projects` is written only by the person's moves (`rig open`, `rig share`, `rig unshare`), each
  refused from a session's tool call (`caller.person_refusal`); a session with no list serves every project.
- Older flotillas fold the new fields as they fold today: nothing renamed, nothing removed.
- Public tree rules: no personal names, home paths or other projects; lines at most 120 characters; no Cyrillic.

## Review Focus

1. **Several waiters polling at once under `fair`, capacity 2**: never more live holders than the slots; the fair
   choice decided inside the lock from the bookings read there. Test in Task 1.
2. **A fair choice that is dead, or taken by hand**: a dead waiter is never the choice; a `lane take` waiter waits as
   its process and is chosen like any other. Test in Task 1.
3. **A project string another session wrote** (escapes, very long) in `flotilla lane`, `rig status` and the
   refusal: shown through `visible`, bounded. Test in Tasks 2 and 5.
4. **`rig share` of the project already on the list, or `unshare` of the last one**: the first says so and changes
   nothing; the second is refused, naming `rig close` (a session serving nobody is a closed one). Test in Task 3.
5. **Overlapping runs on two machines of one session**: each machine's minutes split among its own runs only; shares
   plus idle equal `spent`, to the cent. Test in Task 5.

---

## Calls this plan makes

1. **The 24-hour window** is read from the bookings already folded: a booking counts as a service when its state is
   `held`, or `released` without `inside`, and its `since` is within 24 hours of now.
2. **`lane_share` is read with `lane_capacity`** in one `machine.toml` read per poll (`commands.capacity` and a new
   `commands.share` share the reader), passed to `acquire`/`held` as a callable like the capacity.
3. **The refused rig run's request** is a new request kind, `share`, so the orchestrator's surface shows it while a
   session is open (it hides `machine` requests then); the person's `rig share` answers it.
4. **Projects are named by key** in `rig share`/`unshare`; a path is accepted and turned into its key, and the output
   prints the key it recorded.

### Task 1: the fair choice in `grant`

now) -> Booking | None`, `grant(..., share="fifo")`), `flotilla/lane/acquire.py` (`acquire`/`held` take `share`, a
string or a callable, read per poll like the capacity). Test: `tests/test_lane_book.py`, `tests/test_lane_acquire.py`.

**Interfaces:**
- Produces: `fair_choice(found: dict, live: Callable[[Booking], bool], now: datetime) -> Booking | None` - the live
  waiter that gets the next slot under `fair`: among projects with live waiters, the fewest live holders, then the
  earliest last service in 24 h (none first), then the oldest waiter; within the project, its oldest waiter.

  choice, or the fair choice is under an older rule and nothing live waits ahead of it; the `held` event carries
  `path` (`fifo`, or `fair: <project> served <when or never>`).
