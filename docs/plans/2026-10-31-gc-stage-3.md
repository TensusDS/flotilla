# Garbage collection, stage 3: occasions and the disk - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The collector stops depending on someone remembering to run it: a dead session's tree, a shipped batch, a
finished helper and released work each bring a pass; a daily pass the orchestrator keeps is the net under them; a
low disk shrinks idle trees and stops new work before it runs out; and the archive empties itself of media after a
month, but only on the person's recorded yes.

**Architecture:** Five new modules in `flotilla/gc/`: the disk's state (`disk.py`), shrinking idle trees and the
letter about a live tree's outputs (`shrink.py`), dead seats (`dead.py`), the archive's lifetime and its question
(`expiry.py`), and the due marks the daily pass reads (`due.py`). The daily pass is `flotilla fleet clean --daily`;
`watch` names it as an item when it is due, so the orchestrator's own `watch --wait` loop is the schedule. `ship`,
`helper done` and `release` only mark the pass due. Spawn, `helper raise` and the lane refuse new work with no room.
Released work's unlanded branch becomes a question (park or keep). `gc next`, `gc answer` and `gc apply` gain the
expiry question.

**Tech Stack:** Python 3.11+ stdlib (`shutil`, `mimetypes`, `datetime`), git >= 2.38 through `subprocess`, pytest
through `uv run --with pytest python -m pytest -p no:cacheprovider -q tests/`.

**Spec:** `docs/specs/2026-10-21-gc-design.md` (approved by the person 2026-10-27). Sections implemented here: 4 e-k,
7's lifetime (steps 1-6, media only), 8 (low, no room, shrink, the letter to a live session), and 9 for what these
occasions report. Stages 1 and 2 shipped the rest in 0.22.0 and 0.23.0. Plans of those stages:
`docs/plans/2026-10-27-gc-stage-1.md`, `docs/plans/2026-10-28-gc-stage-2.md`.

## Global Constraints

- The person's rule: nothing is deleted for good without the person's recorded word. An unanswered question never
  turns into a deletion; it blocks only its own item, never a pass, a session's exit or the daily pass.
- **A live session's tree is never touched**, by shrinking or anything else: an open row for a live owner, a live
  session's cwd, or any process with its cwd in the tree holds it (`trees._alive`, `leftovers.working_in`).
- Disk thresholds (the design's, the profile may change them): **low** is free space under the smaller of 10 % of
  the volume and 20 GB (`[gc] disk_low_percent = 10`, `[gc] disk_low_mb = 20480`); **no room** is under 2 GB
  (`[gc] disk_no_room_mb = 2048`). Read with `config.whole_number`, a bad value falls back with a note.
- With no room the fleet starts no new session and the lane admits no new run; **live sessions are not stopped**.
- "Idle" for shrinking: no open row holds the tree for a live session, no process has its cwd in it, and neither its
  index nor its HEAD (the tree's git dir `index`, `HEAD`, `logs/HEAD`) changed in the last 24 hours.
- The archive lives one month (30 days from the entry's `when`); the expiry question comes 3 days before; no answer
  and the disk has room: asked again the next day; ignored three times: the entry stays another month, or until the
  disk runs low; low disk: asked at once. **Expiry takes media only** (video, audio, images, renders by content
  type); scripts, logs, json, notes, patches and parked commits never expire.
- Questions keep stage 2's rules: an answer is bound to the fingerprint of what the person was shown; `gc answer`
  and `gc apply` refuse a background session (`caller.person_refusal`); a relayed "the person said yes" approves
  nothing.
- Who speaks to the person: the collector's reports and questions reach the orchestrator; a live session gets a
  letter only about its own tree (the outputs letter), printed in `letters.render`'s shape for the caller to send.
- Public tree: no personal names, home paths or other projects in code, tests or docs. Lines at most 120
  characters; no Cyrillic in the tree. Tests that make commits pass `*IDENTITY` from `tests/ledgerkit.py`; no
  `sed -i` in tests.

## Review Focus

1. **A running session the census does not list for a moment** (a restart, a census read between two writes).
   Expect: it is not retired - a process with its cwd in the tree, or a census that cannot be read, means nothing is
   done. Test in Task 5.
2. **Low disk and a live session's tree holding `node_modules`.** Expect: untouched; only idle trees shrink. Test in
   Task 3.
3. **One archived object shared by an entry that expires and a newer one that does not.** Expect: the object stays;
   only the expired entry's record of it is marked. Test in Task 7.
4. **A yes to the expiry question, then media from a new entry becomes due before the month ends.** Expect: the yes
   covers only what was shown (fingerprint); the new media is asked about. Test in Task 7.
5. **`shutil.disk_usage` raising** (the path gone, a permission). Expect: the disk is "unknown": nothing refused,
   nothing shrunk, one note. Test in Task 1.

## Calls this plan makes (the design left them to the builder)

1. **The daily pass is the orchestrator's own loop, not a cron.** `watch` raises a `collector` item when the pass is
   due (a due mark, or a day since the last pass) and a `disk` item when the disk is low; the orchestrator's template
   says to run `flotilla fleet clean --daily` on either. Cost if wrong: with no orchestrator alive no daily pass runs;
   `flotilla doctor` still names dead seats, and `fleet clean` stays the manual sweep.
2. **`ship`, `helper done` and `release` only mark the pass due**; the pass runs in the orchestrator's daily pass.
   Shipping stays fast, a batch gets one pass, and the report reaches the orchestrator because the orchestrator runs
   it. Cost if wrong: trees wait until the orchestrator's next wake, at most an hour (`watch --wait 3600`).
3. **A dead seat** is a post row (`reserved`) or a finished helper's seat whose owner the census does not list,
   whose tree exists, and in whose tree no process works (`leftovers.working_in` returns `[]`; `None` means "cannot
   tell" and the seat is left). It is retired exactly as `retire` does for a session already gone. Claimed work of a
   dead owner is not touched: it is orphaned work for `adopt`. Cost if wrong: a dead seat whose tree a stray
   process keeps busy waits for the next pass.
4. **No record of a rig download in flight exists**, so "no room" is the 2 GB floor only; the design's "or under
   what a rig download in flight still needs" goes to TODO.md. Cost if wrong: a large `rig --get` can still fill the
   disk past the floor.
5. **`--anyway` does not cover no room.** It stays the memory floor's override; a full disk is freed or the archive
   is settled. Cost if wrong: the person frees space before a seat they wanted at once.
6. **The outputs letter**: a live session's home tree whose ignored, non-regenerable files pass `[gc] outputs_mb`
   (default 1000, the design's 1 GB case) gets one letter naming the five largest, at most once a day per tree.
7. **Expiry is carried out by the daily pass on the recorded yes**, when an entry's month has ended (the person was
   told "in 3 days I remove"); `gc apply` carries it out too when the date has come. The yes is the authority, the
   collector the only one acting on it, as in stage 2. Cost if wrong: media removed at the date said, not at once.
8. **An archived object is deleted only when no unexpired record points at it** (stage 2 stores identical content
   once); an expired record stays in `entry.json` marked `expired` with when and by whose answer, and `restore`
   names it instead of failing.
9. **Released work's branch** (its latest row `released`, its commits on no trunk) is asked as `park` (the tip and
   reflog-only commits parked, the branch deleted; the line names `git branch <name> <parked ref>` to undo) or
   `keep`. Its tree is judged as before: the branch holds its commits, so the tree may already go.
10. **Shrinking removes only entries git ignores whose name is regenerable** (`ignored.REGENERABLE`, its suffixes
    and `[gc] regenerable`), under the collector's own worktree lock (`trees.GC_LOCK`), links removed as links.
