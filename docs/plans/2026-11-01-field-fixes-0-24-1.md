# Field fixes 0.24.1: the lane's visible state, `--requires`, and a wait's name - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The fixes two field fleets asked for that each cost hours on 2026-10-31..11-01 and each mend one place: a
lane capacity change reaches every waiter, `flotilla lane` says who really holds the slots and why a waiter waits,
`--requires` keeps every row it is given and can be amended on the record, and a wait on a short name finds the live
session it means.

**Architecture:** No new module. `lane/acquire.py` reads the capacity on each poll; `lane/commands.py` prints foreign
runs where the slots are, each waiter's reason, and sweeps dead bookings when it shows the lane; `lane/procs.py`
gains a process's working directory. The CLI's `--requires` accumulates; `work show` prints the links; a new
annotation move `requires` (owner or a post that may) adds or drops links, refusing a drop the tip still needs;
`work wait --on` resolves a short name against the census.

**Tech Stack:** Python 3.11+ stdlib, git >= 2.38 through `subprocess`, pytest through
`uv run --with pytest python -m pytest -p no:cacheprovider -q tests/`.

**Spec:** the field reports, recorded in `TODO.md` ("From two field fleets", checked 2026-11-01 on a50daae):
`alpha-keep/flotilla-feedback-2026-11-01.md` items 1, 2, 5, 9 (first bullet), 10, 11, and the gamma
lane report's last section. The lane's modes (0.25.0) and the rig queue (0.26.0) are not in this plan.

## Global Constraints

- FIFO admission is unchanged: no waiter is admitted out of order by this plan.
- A run already holding a slot is never stopped or released by a capacity cut; a cut only stops new grants.
- `machine.toml` read failures keep today's fallback: capacity 1, never an exception in a waiter.
- Text another session wrote (commands, notes, names, cwds) is printed through `core.text.visible`.
- A refusal names the way forward. A move is recorded in the ledger with its evidence; nothing edits a row's fields
  outside a move.
- Public tree: no personal names, home paths or other projects in code, tests or docs. Lines at most 120
  characters; no Cyrillic in the tree. Tests that make commits pass `*IDENTITY` from `tests/ledgerkit.py`.

## Review Focus

1. **Capacity lowered while two runs hold** (2 -> 1). Expect: both keep running; no grant until one releases and
   the holders are under the new capacity. Test in Task 1.
2. **`machine.toml` torn or unreadable while a waiter polls.** Expect: that poll uses capacity 1, the waiter keeps
   waiting, no traceback. Test in Task 1.
3. **`--requires a b --requires c`, and the same row twice.** Expect: `[a, b, c]` in order, duplicates once. Test in
   Task 3.
4. **Dropping a requirement whose row is gone, closed, or whose commits are all on trunk.** Expect: allowed when the
   tip carries none of its commits off trunk; refused with the commit count otherwise; an unknown name refused by
   name. Test in Task 4.
5. **`wait --on` while the census cannot be asked.** Expect: the name is recorded as written, with a note that it
   was not checked; never a refusal. Test in Task 5.

---

## Calls this plan makes

1. **Dead bookings are swept when the lane is shown**, not on each waiter's poll: since 0.23 `grant` already skips a
   dead holder and a dead waiter, so a dead booking blocks nobody; it only misleads the reader of `flotilla lane`.
2. **`work requires` is an annotation move** (like `walkable`): it keeps the row's state and may be made by the
   row's owner or a post whose `may` lists `requires` (the orchestrator template gains it, template 22).
3. **A drop is refused when the tip carries commits of the dropped row that are not on trunk** - the check the alpha
   orchestrator ran by hand. An add needs no check beyond naming a known row.
4. **A short wait name resolves only to exactly one live session** whose name is the short name or ends with
   `-<short name>` or ` <short name>`; it is refused only when it names a session the ledger knows that the census
   does not list and nothing live matches. Free words (`the lane`, `CI`) stay free.
